# V22 Browser E2E Foundation & Role Verification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add dependency-free real-Chrome end-to-end coverage for Srocial authentication, RBAC, Admin user management, and session revocation.

**Architecture:** A Node 22 test helper launches the real Srocial server in an isolated JSON/temp-media environment and launches headless Chrome through the Chrome DevTools Protocol. A dedicated `.e2e.js` suite drives the real login/dashboard DOM, performs same-origin API boundary probes with the browser's real cookie, and exercises Admin Users workflows. Existing `npm test` remains unchanged; CI adds a separate `npm run test:e2e` gate.

**Tech Stack:** Node.js 22 built-ins (`node:test`, `child_process`, `http`, `net`, `fs/promises`, global `fetch`, global `WebSocket`) + installed Google Chrome/Chromium + existing Srocial server.

**Spec:** `docs/superpowers/specs/2026-09-15-browser-e2e-v22-design.md`

## Global Constraints

- Do not add provider credentials or real provider calls.
- Keep `SCHEDULER_ENABLED=false`, `ALLOW_REAL_PUBLISH=false`, and `ALLOW_REAL_WHATSAPP=false` in E2E runtime.
- Do not add a production test-only endpoint.
- Do not add Playwright/Puppeteer/Selenium dependencies.
- Existing `npm test`, PostgreSQL migration coverage, and syntax checks must remain green.
- Browser tests must fail rather than silently skip when Chrome is unavailable in CI.
- `SR-P001` remains partially open after this milestone for untested operator surfaces.

### Task 2: Implement isolated Srocial E2E server fixture

**Files:**
- Create: `tests/e2e/srocial-server.js`

**Interfaces:**
- Produces: `startSrocialE2EServer(): Promise<{ baseUrl, admin, close }>` where `admin` contains test-only username/password and `close()` terminates the child process and removes temporary files.

- [ ] **Step 1: Implement free-port selection and temp fixture directory**

Use `node:net` to bind port `0` on `127.0.0.1`, close it, and reuse the selected port. Use `mkdtemp` under `tmpdir()` for `DATA_FILE` and media storage.

- [ ] **Step 2: Spawn the real server with safe E2E environment**

Spawn `node server/server.js` from repository root with:

```text
APP_AUTH_ENABLED=true
ADMIN_USERNAME=e2e-admin
ADMIN_PASSWORD=E2E-Admin-Password-123!
SESSION_SECRET=e2e-session-secret-0123456789abcdef0123456789abcdef
DATABASE_DRIVER=json
SCHEDULER_ENABLED=false
ALLOW_REAL_PUBLISH=false
ALLOW_REAL_WHATSAPP=false
MEDIA_ORPHAN_CLEANUP_ENABLED=false
```

and fixture-specific `PORT`, `HOST`, `PUBLIC_BASE_URL`, `DATA_FILE`, and `MEDIA_UPLOAD_DIR`.

- [ ] **Step 3: Poll `/api/health` with a bounded timeout**

Resolve only after HTTP success. On timeout/process exit, throw a sanitized startup error and clean up.

- [ ] **Step 4: Implement deterministic cleanup**

`close()` sends `SIGTERM`, waits boundedly for exit, escalates to `SIGKILL` if required, and removes the fixture directory recursively.

### Task 3: Implement dependency-free Chrome/CDP driver

**Files:**
- Create: `tests/e2e/browser-driver.js`

**Interfaces:**
- Produces: `launchBrowser(): Promise<{ navigate, evaluate, waitFor, fill, click, submit, close }>`.

- [ ] **Step 1: Discover and launch Chrome**

Use `CHROME_PATH` first, then common Linux locations. Spawn with:

```text
--headless=new
--no-sandbox
--disable-dev-shm-usage
--remote-debugging-port=<free port>
--user-data-dir=<temp dir>
about:blank
```

- [ ] **Step 2: Connect to the page target over CDP**

Poll `http://127.0.0.1:<debugPort>/json/list`, read the first `page` target's `webSocketDebuggerUrl`, connect using Node 22 global `WebSocket`, and implement id-correlated request/response handling.

- [ ] **Step 3: Implement DOM/navigation helpers**

Enable `Page` and `Runtime`. Implement:

```js
await browser.navigate(url);
await browser.evaluate(expression);
await browser.waitFor(expression, { timeoutMs });
await browser.fill(selector, value);
await browser.click(selector);
await browser.submit(selector);
```

`waitFor` retries transient execution-context errors across navigation and throws on timeout.

- [ ] **Step 4: Implement cleanup**

Close WebSocket, terminate Chrome, and remove the temporary profile.

- [ ] **Step 5: Run `npm run test:e2e`**

Expected: helper imports resolve and tests advance to real application assertions. Fix helper-only failures before changing product code.

- [ ] **Step 2: Verify unauthenticated redirect + Admin surface**

- [ ] **Step 3: Create Viewer, Editor, and Manager through the Users UI**

Submit `#user-create-form` with deterministic credentials and wait for `#users-feedback` to report success after each create.

- [ ] **Step 4: Verify browser-session authorization matrix**

For each role, login through UI and issue same-origin `fetch` probes in `Runtime.evaluate`:

```text

Editor: POST /api/posts invalid payload => 400 (authorized path); POST /api/oauth/instagram/start => 403
Manager: POST /api/oauth/instagram/start => anything except 403; GET /api/users => 403
Admin: GET /api/users => 200
```

For Viewer/Editor/Manager, Users navigation must remain hidden; for Admin it must be visible.

- [ ] **Step 5: Run E2E and verify GREEN for authorization scenarios**

Expected: all auth/RBAC browser assertions pass without provider credentials.

### Task 5: Complete Admin user lifecycle + revocation browser tests

**Files:**
- Modify: `tests/e2e/auth-rbac.e2e.js`

- [ ] **Step 1: Create a lifecycle user through the Admin UI**

Create an Editor user and locate its `.user-card` by `@username` text using browser-side DOM code.

- [ ] **Step 2: Update role/display name and verify rendered state**

Change role to `MANAGER`, update display name, click `Save user`, wait for `#users-feedback`, and assert the refreshed card reflects the new values.

- [ ] **Step 3: Change password and verify credential rotation**

Use the card's `aria-label="New password for <username>"` input and `Change password` button. Log out Admin, verify the old password fails and the new password succeeds.

- [ ] **Step 4: Disable user and verify login denial**

Return as Admin, set status `DISABLED`, save, log out, and assert disabled credentials show `Invalid username or password.`.

- [ ] **Step 5: Verify explicit session revocation**

Create a separate active user. Obtain one normal session via `POST /api/auth/login` in Node, retain only the `Set-Cookie` header in memory, click that user's `Revoke sessions` action in the Admin browser, then assert `GET /api/auth/session` with the old cookie returns `401`.

- [ ] **Step 6: Run E2E and full existing tests**

Expected: `npm run test:e2e` green and `npm test` still green.
